How RSM Works
=============

When you run ``rsm build manuscript.rsm``, your source passes through six
stages. Understanding this pipeline helps you debug problems and extend RSM.


Read
----

The source file is read into a string.

- **Input**: path to ``.rsm`` file
- **Output**: string with RSM source
- **Module**: :mod:`~rsm.reader`


Parse
-----

The source string is parsed into a tree in two sub-steps.

1. **Concrete syntax tree (CST)**: A C parser generated by
   `tree-sitter <https://tree-sitter.github.io/tree-sitter/>`_ tokenizes the
   source. The CST contains every syntactic element: tags, Halmoses, braces,
   whitespace. This tree powers syntax highlighting and editor features.

2. **Abstract syntax tree (AST)**: The CST is *abstractified* into a
   manuscript tree made of :mod:`~rsm.nodes` objects. Syntactic noise is
   stripped; only semantically meaningful nodes remain (sections, theorems,
   references, bibliography entries).

Editor tools and the LSP may stop at the CST. Everything downstream works
with the AST.

- **Input**: string with RSM source
- **Output**: abstract manuscript tree
- **Module**: :mod:`~rsm.tsparser`


Transform
---------

The AST is finalized through several passes:

- **Reference resolution**: forward references (``:ref:`` before ``:label:``)
  are linked to their targets. Citations are resolved against the bibliography.
- **Autonumbering**: theorems, equations, and sections receive numbers.
- **Table of contents**: generated from the section tree.
- **Proof adornments**: turnstiles, QED symbols, and other structural markers
  are inserted.

After transformation the tree is frozen. Tools that only need an in-memory
representation (like ``rsm check``) stop here.

- **Input**: abstract manuscript tree
- **Output**: finalized manuscript tree
- **Module**: :mod:`~rsm.transformer`


Lint (optional)
---------------

The linter checks the finalized tree for consistency: missing labels,
unreferenced bibliography entries, structural problems. It does not modify the
tree.

- **Input**: finalized manuscript tree
- **Output**: warnings and suggestions
- **Module**: :mod:`~rsm.linter`


Translate
---------

Each node in the manuscript tree is visited and translated into HTML. There are
two translators:

- **Basic translator**: generates clean HTML. Used by ``rsm render`` and in
  automated testing.
- **Handrails translator**: adds interactive features (collapse controls,
  context menus, tooltip anchors, structural borders). Used by ``rsm build``.

This step produces only the ``<body>`` of the final document.

- **Input**: finalized manuscript tree
- **Output**: HTML body string
- **Module**: :mod:`~rsm.translator`


Build
-----

The HTML body is wrapped in a complete document: ``<head>`` with metadata,
stylesheets, and scripts. Static assets (CSS, JavaScript, images) are
gathered into an in-memory file tree.

- **Input**: HTML body string
- **Output**: in-memory representation of the output folder
- **Module**: :mod:`~rsm.builder`


Write
-----

The in-memory file tree is written to disk as ``index.html`` plus a
``static/`` folder.

- **Input**: in-memory file tree
- **Output**: files on disk
- **Module**: :mod:`~rsm.writer`
